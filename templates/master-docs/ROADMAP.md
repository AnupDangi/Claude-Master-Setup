# Roadmap

> The loop consumes this top-to-bottom. Each item must be a **single shippable unit**
> with a clear outcome. Break anything large into slices. Generated by `/bootstrap`,
> refined as you go.

## How to read this
- `[ ]` not started · `[~]` in progress · `[x]` done · `[!]` blocked
- Order = build order. The orchestrator picks the topmost unblocked item — sizing an
  oversized pick down to a shippable slice is PLAN's job (via a Task Graph).
- Optionally append `(depends: <other item>)` to declare an ordering requirement
  beyond plain file order.
- **Anti-pattern:** 15+ micro-items for a small app. Prefer coarse milestones.
